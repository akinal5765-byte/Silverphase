# 界面规范 — Silverphase 主编辑器

一句话:这份文件定义界面的**结构、设计语言、组件行为、交互模型**。

**它是界面的最高权威。** 原始项目的参照图与 `TOKENS-main-v3-2026-09-18.md` /
`tokens-main-v3.json` 是**参考素材,不是规范** —— 它们描述上游产品的界面,我们不欠它
一致性。`Theme.swift` 是我们自己的 token 源,可以改,改了要同步 §2。

| 内容 | 唯一来源 |
|---|---|
| 信息架构、控件归属、组件行为、交互 | **本文件** |
| 颜色、字号、间距的当前取值 | `Theme.swift`(这里只写规则,不写数字) |
| SwiftUI 实现约束(用什么、不用什么) | `../UI-GUIDELINE-swiftui.md` |
| 中文文案与术语 | **本文件 §7** |
| 参照图(`../reference_layout/`) | 素材,可看不必遵守 |
| 本文与代码冲突 | **以本文为准**:规范是主张,代码是要被改的东西 |

## 1. 信息架构

### 1.1 区域

窗口分成六个区域,每个区域有且只有一类职责:

| 区域 | 只管 | 绝不放 |
|---|---|---|
| 菜单栏 | 帧级动作、视图状态、快捷键 | 影响渲染的数值 |
| 顶栏(工具栏) | 文件动作、视图状态、工具、两侧栏折叠 | 渲染参数 |
| 左栏(**预设**) | 胶片与相纸的选择(资源) | 参数微调、文件动作 |
| 画布 | 图像、只读叠加层、拾取类工具、直接操作 | 可编辑参数、一次性动作按钮 |
| 右栏(**参数**) | 影响渲染的参数 | 资源选择、文件动作 |
| 底栏(胶片条) | 选帧、单帧动作 | 参数 |
| 导出页 / 设置页 | 导出设置 / 应用偏好 | 单帧参数(只读回显可以) |

**用词先钉死**,不要再用"检查器"这个词:缩略图是**胶片条**(底栏),参数是**参数栏**
(右栏),胶片与相纸列表是**预设栏**(左栏)。

**布局与 Lightroom Classic 一致**:左预设、中画布、右参数、底胶片条。理由不是模仿,
是分工 —— 选一款胶片是"换一套配方",调一个滑杆是"改这套配方",两者是不同的动作,
放在不同的栏里,用户就不用在一个长栏里找东西。现在的代码把两者塞在同一个左栏,
这正是"按钮位置没有逻辑"的来源。

### 1.2 一个控件只有一个家

| 控件 | 归属 | 理由 |
|---|---|---|
| 胶片 / 相纸的选择(换配方) | 左栏(预设) | 这是"换一套",不是"改一处" |
| 滑杆、开关、下拉(改渲染) | 右栏(参数)对应分区 | 分区就是物理流程的一段 |
| 只读数值、状态徽章、直方图 | 画布叠加层(右上角) | 不是可操作的东西 |
| 分区级重置 | 该分区标题栏的 •••,文案写明作用范围 | 标题栏的动作作用于标题栏这一区 |
| 帧级重置、复制/粘贴设置 | 菜单栏 Frame | 跨分区的动作没有归属区 |
| 视图状态 | 顶栏;**菜单栏也有同一动作**,这是允许的例外 | 菜单是快捷键的可发现形式 |
| 解释性文字 | 该控件的 `.help(...)` | 不占版面 |

### 1.3 六条硬禁止

1. 同一控制不在两处(§1.2 最后一行除外)。
2. 画布上不放可编辑控件,也不放一次性动作按钮。
3. 文案里不写死配置名或 ID。
4. 新控件不许用 token 之外的字面量。
5. 不许有"只在默认值下才存在"的控件:任何会被持久化的设置都要能被找到、能改回。
6. 不许出现没有原因的禁用态。

### 1.4 骨架

```
┌──────────────┬──────────────────────────────┬──────────────┐
│ 顶栏  打开·导出 │   缩放 · 适合 · 对比 · 全屏     │ 叠加层 · 折叠 │
├──────────────┼──────────────────────────────┼──────────────┤
│ 预设栏(左)    │  画布                          │ 参数栏(右)    │
│  胶片列表      │   右上角: 直方图(只读)          │  输入 / 相机  │
│  相纸列表      │   其下:   徽章                 │  胶片         │
│              │                              │  显影         │
│              │                              │  印相         │
│              │                              │  裁剪         │
├──────────────┴──────────────────────────────┴──────────────┤
│ 胶片条                                                       │
└────────────────────────────────────────────────────────────┘
```

分区内容(每个参数只有一个家,全部在**右栏**):

| 分区 | 内容 |
|---|---|
| 输入 / 相机 | 测光方式、胶片曝光、白平衡(色温 / 色调)、镜头校正 |
| 胶片 | 胶片画幅(类型 / 基准边 / 边长)、颗粒、胶片晕光(档位 + 晕光强度) |
| 显影 | 显影反差、色彩分离 |
| 印相 | 印相曝光、黄色滤光、品红滤光、预闪、印相眩光、扩展动态范围、不使用相纸配置 |
| 裁剪 | 宽高比、拉直、旋转、翻转 |

**左栏只有选择,没有数值**:两款列表(胶片、相纸)属于左栏;选中之后这款胶片的**参数**
属于右栏。同一个胶片既在左栏(被选中)又在右栏(参数)出现是正常的 —— 那是两个不同的
动作,不是"同一控制两处"。

**放大机区删除**(不只是 flag 关掉):印相曝光与黄/品红已经在「印相」区有家。
将来若要暴露光源,它是「印相」区里的一行,不是新分区。

## 2. 设计语言与材质

### 2.1 密度与节奏

- 一个控件一行。行高、控件高、行间距一律取 `Theme.Metric`,不在 View 里写数字。
- 分区内行与行**等距**;分区之间靠 hairline + `sectionBottom` 分隔。
- 参数区的目标是"一屏读完一个分区",不是"每行都很大"。宁可行短、间距准。
- **不给控件加内边距来"透气"**;透气靠行间距。控件高就是控件高。

### 2.2 表面:只有五层

一个表面 = **填充 + 内描边 + 顶部高光 +(可选)落影 + 圆角**。层次只由这五件事表达,
不由边框粗细表达。

| 层 | 名称 | 用在哪 | 圆角 |
|---|---|---|---|
| L0 | ground | 窗口底 | 0 |
| L1 | card | 两侧栏、胶片条 | 0 |
| L2 | well | 列表、直方图的凹槽 | 小 |
| L3 | control | 药丸、字段、按钮、滑杆轨道 | 控件圆角 |
| L4 | overlay | 画布叠加层、菜单 | 只有这层可有较大圆角与落影 |

规则:

- 每层比它下面一层亮或暗**一个固定步长**;步长写进 `Theme`,不在 View 里调。
- 每个表面有一条 **1px 内描边:上半亮(白 6–10%)、下半暗(黑 15–25%)**。
  这一条是"质感"的主要来源 —— 没有它,控件就是一张色块。
- **L0–L3 一律不投影。** 落影只属于 L4。
- 填充允许极淡的垂直渐变(顶亮约 2%),不允许纹理、不允许玻璃拟态。

`Theme` 需要为此新增一组 token(第 1 期做):内描边的上下两色、hover / pressed 的填充、
轨道的两段色、滑块描边与落影、L4 落影。**这些值只存在于 `Theme`,View 里不许出现数字或即席色。**

### 2.3 控件的状态

药丸 / 字段 / 按钮统一三层:填充、内描边、内容。状态做法固定:

| 状态 | 做法 |
|---|---|
| default | 填充 + 上亮下暗内描边 |
| hover | 填充提亮约 6%;内描边同步提亮 |
| pressed | 填充压暗约 4%;内描边**翻转**(上暗下亮),产生"按下去"的错觉 |
| focus | 外圈 2px accent + 1px 间隙;**不改变填充** |
| disabled | 整体 38% 不透明度,但**保留内描边**(不能塌成半个控件);必须能说出原因 |
| selected | 见 §2.4 |

### 2.4 列表与选中

- 列表坐在 **well** 里,不是坐在 card 上。
- 选中 = 白色胶囊 + 1px 暗描边 + 极淡落影 + `onSelection` 文字;胶囊比行窄 2pt,不顶到边。
- hover = 淡填充(白 4–6%);**不加描边、不位移、不缩放**。

### 2.5 滑杆

- 轨道高约 3pt、全圆角;未过部分用暗版 rule,**已过部分用亮版 rule** —— 不用 accent,
  accent 只留给真正的"看这里"。
- 滑块直径约 9pt:1px 亮描边 + 1px 落影。hover 时**滑块不变大**,轨道提亮。
- 数值药丸固定宽度、等宽数字、右对齐。
- 拖动中:已过轨道与滑块同时提亮一档,数值药丸反白。

### 2.6 分隔与文字

- hairline:1px、**白 8%**。纯色线看起来像画上去的。
- 分区之间用 hairline;**行与行之间不用线**,用间距。
- 文字三级 `text / secondaryText / dim`;中文走系统中文回退,保持粗体语义。
- 数值一律 `monospacedDigit` + 右对齐;单位属于标签,不属于数值。

### 2.7 字体阶梯

只有四档,不新增:

| 档 | 用途 |
|---|---|
| 分区标题 | 区名 |
| 正文 | 胶片区的标签、列表分组标题 |
| 小号 | 相机区的标签、所有控件值 |
| 等宽数字 | 一切会变化的数值(缩放、EV、百分比) |

中文与英文配置名混排时**不要为了塞进去而降字号**;调整标签列宽。

### 2.8 图标

- 一律 SF Symbols,统一 weight;只有两档尺寸(栏头 / 行内)。
- 与相邻文字**光学对齐**,不是按字号框对齐。
- 纯图标按钮命中区 26×26,必须有 `.help(...)`。
- 图标不表达状态;状态用颜色、文字或位置。

### 2.9 画布叠加层

画布上的东西是**画在照片上**的,不是浮在照片上的卡片:

- 它属于 L4,但**只允许落影,不允许底板颜色、圆角、内边距**。
- 可读性靠一层极淡的顶部渐变压暗(约 12% → 透明),不靠一块灰。
- 直方图固定在**右上角**,徽章在其下方,共用一条纵向间距规则。
- 叠加层可开可关,顶栏给开关,状态持久化,默认开。
- 叠加层不拦截拖动;除拾取类工具外,画布上的点击都属于画布。

### 2.10 什么会显得廉价(禁止)

| 禁止 | 改成 |
|---|---|
| 用纯色 1px 边框勾控件 | 上亮下暗的内描边 |
| 每层都加圆角和投影 | 投影只给 L4 |
| hover 时位移、放大、抖动 | 只改填充与描边 |
| accent 到处用 | accent 一次只在一处 |

**accent 的定义(2026-09-23,用户要求)**:`Theme.accent` = **Apple 橙 `#FF9F0A`**
(`NSColor.systemOrange` 的深色外观取值;浅色版是 `#FF9500`)。理由就是 accent 唯一的
工作是"被认出来",而人认得的橙是系统那个 —— 它替掉了 v3 图纸采样出来的 `#E1A95F`
(一个土黄)和更早的 `#ee8a2b`。写成字面值而不是 `Color(nsColor: .systemOrange)`,
是为了不让界面在系统外观/辅助功能设置/OS 更新下移动。

**而且它不再渐变** —— 同一句要求的下半段:"橙色不需要渐变了,这样显得更专业"。顶光
(`pillSurface(wash:)`)是**灰色材质**用来表示"这是一块浮起来的表面";放在整个界面唯一
用来当**信号**的颜色上,它读起来就成了一个亮面按钮,而信号本身就是全部意义。所以:
- `pillSurface(base:wash:)` 新增 `wash`;accent 板一律 `wash: false`
  (主按钮 `SurfaceButton`、导出页主按钮、导出页命名 chips)。
- `ScrubSlider` 的复选框原来在选中时是 `accent → accent.opacity(0.80)` 的渐变,
  现在是纯 accent。
- **1px 描边留着**:那是材质的边,不是橙色。
- 不属于这一条的橙色有两处,都是**照片的东西而不是界面**:擦除动画里那盏暖色灯
  (`Shaders.metal` 里的 `float3(1.0, 0.87, 0.64)`)和底片本身的橙色罩(引擎的物理),
  以及白平衡轨道的 `#FFF100` 端点(那是**色标**,不是装饰)。
| 数值用比例字体(会左右跳) | 等宽数字 |
| `Color.gray` / `.black.opacity()` 这类即席色 | `Theme` token |
| 系统材质 / 玻璃拟态 / 毛玻璃 | 五层表面 |
| 一张图里出现两种圆角 | 一种控件圆角 |
| 大图标、插图、吉祥物式空态 | 一句话 + 一个动作 |

### 2.11 动效

以 §6 为准。摘要:hover 约 100ms、按下即时、面板折叠约 180ms;**数值变化不动画**。

## 3. 组件规范

每个组件必须写清**结构 / 状态 / 交互**三件事。状态至少包含
default、hover、active、focus、disabled 五种;缺哪个要有理由。

### 3.1 滑杆(参数的主力)

- 结构:标签列 | 轨道 | 数值药丸。单位与方向写在标签的第二行,不写进数值。
- 交互:
  - 拖动轨道:改值,按 `snap` 吸附。
  - 拖动**标签**:同样改值(scrub),这是老手的路径。
  - 双击标签或数值:回到该参数的默认值(`zero` 或默认档)。
  - 单击数值:进入输入,回车提交,Esc 取消,非法输入回弹并提示。
  - 键盘:聚焦后方向键 ±1 步,⇧ 方向键 ±10 步。
- 状态:hover 时轨道提亮一档;active 时数值药丸反白;focus 时有一致的焦点环;
  disabled 时必须能通过 tooltip 说出原因。
- 拖动整段只算**一次撤销**。

### 3.2 下拉药丸

- 结构:标签 | 药丸(当前值 + 折角)。
- 交互:点击展开;菜单项当前项带勾;上下键选择,回车确认,Esc 关闭。
- 值多到超过 5 个时,考虑换成带搜索的菜单,而不是更长的列表。

### 3.3 开关行

- 整行可点,不是只有开关可点。
- 关掉一个开关时,**它管辖的从属控件一起置灰**,并保留在原位(不塌陷、不消失)。

### 3.4 分组列表(胶片 / 相纸)

- 正面/负面、静态摄影/电影是分组标题,不是可选项,不参与键盘选择。
- 选中用白胶囊 + 深色字;hover 用淡底;键盘上下移动选择,回车确认。
- 列表本身可滚动,滚动条不常显;分组标题吸顶。

### 3.5 数值字段

- 可输入。非法值不静默接受:回弹 + 说明。
- 单位属于标签,不属于输入框;输入框里只有数字。

### 3.6 按钮四级

| 级别 | 用途 | 出现位置 |
|---|---|---|
| 主按钮 | 一屏一个,推进流程(自动测光与配光) | 分区底部 |
| 次按钮 | 重置、次要动作 | 分区底部或标题栏 ••• |
| 图标按钮 | 视图类、工具类,有 tooltip | 顶栏、栏头 |
| 危险按钮 | 删除类 | 菜单内,或带确认 |

同一屏不出现两个主按钮。

### 3.7 分区头

- 结构:展开三角 | 标题 | (可选)•••。
- 整行可点开关;••• 里的动作必须与分区同域,并写明作用范围。
- 展开/收起状态属于用户偏好,持久化。

### 3.8 空态

- 一句中文说清"这里为什么是空的",加一个动作(如胶片条:按 ⌘O)。
- 空态不用插图、不用大图标。

## 4. 交互模型

### 4.1 鼠标与修饰键

| 操作 | 结果 |
|---|---|
| 拖动滑杆标签 | 调值(scrub) |
| 双击标签 / 数值 | 复位到默认 |
| ⇧ + 拖动 / 方向键 | 精调(10× 更细 / ±10 步) |
| ⌥ + 拖动 | 减速,便于精确定位 |
| 右键 | 上下文菜单(画布、列表、参数行) |
| 滚轮 / 触控板 | 画布缩放(以指针为中心);列表滚动 |

**同一个操作在所有同类控件上行为一致。** 一个滑杆能双击复位,所有滑杆都要能。

### 4.2 画布

| 操作 | 结果 |
|---|---|
| 拖动 | 平移(空间键按住 = 临时平移工具) |
| 滚轮 / 双指 | 以指针为锚缩放 |
| 双击 | 在"适合窗口"与 100% 之间切换 |
| 对比模式 | 拖动分界线;Y 键切换 |
| 白平衡吸管 | 按下拾取、松开应用;Esc 取消;拾取时显示放大镜 |
| 裁剪 | 八向手柄 + 三分线;回车提交,Esc 取消 |

### 4.3 键盘

- Tab 能在参数栏里走完所有可交互控件;焦点环统一。
- 分区可用快捷键折叠/展开,但快捷键不写进译文。
- 所有菜单动作都有快捷键,并且**菜单栏与顶栏是同一动作的两个入口**,不是两套实现。

### 4.4 撤销

- 每一次参数改动入栈;⌘Z / ⇧⌘Z。
- 一次拖动、一次输入提交 = 一次撤销,不是每帧一次。
- 视图状态(缩放、面板折叠、叠加层开关)不进撤销栈。

### 4.5 工具提示

- 统一延迟出现,内容包含:它是什么、单位、范围、以及禁用原因(若禁用)。
- 提示文字也算用户可见文案,必须走本地化(§7)。

## 5. 状态与反馈

### 5.1 四种状态,每种都有出口

| 状态 | 表现 | 出口 |
|---|---|---|
| 空 | 一句话 + 一个动作 | 该动作 |
| 忙 | 进度指示 + 可取消 | 取消键 |
| 禁用 | 变灰 + 原因 tooltip | 说明如何解除 |
| 错误 | 一句人话 + 一个可执行动作 | 重试 / 打开位置 |

**不允许出现"看起来能用但没反应"的控件**,也不允许"变灰但不说为什么"。

### 5.2 渲染与加载

- 渲染中:画布角上给状态,不用全屏遮罩。
- 提高分辨率时保留上一张画面,不要闪成空白。
- 超过约 1 秒的阻塞必须能看到反馈。

### 5.3 错误

- 不把系统错误直接抛给用户;包装成"发生了什么 + 怎么办"。
- 不弹模态对话框处理可恢复错误。

## 6. 动效

- 只有三处动画,时长统一:面板折叠(~180ms ease-out)、悬停反馈(即时)、值变化(不闪)。
- **值变化不做动画**:数值等宽,原处刷新。
- 禁止弹跳、缩放、旋转类装饰动画。
- 尊重系统"减弱动态效果"设置。

**「打开即显影」的策略修正(2026-09-23,用户报"拖入照片看到的还是原图,点按钮才出片"):**

查到底后的三条事实:

1. **那个按钮是空的。** ctypes 探针比较"打开后"与"`solve(both)` 后":所有参数一个没变
   (中性滤光值/印相曝光在打开时就是解算值),**像素逐位相同**(0 / 110592 采样点变化)。
   测光在打开时已跑,中性滤光值在 `digest` 里由数据库写入。所以它唯一的效果是**触发重画**。
2. **开发是有门的,而且门不稳定。** `load` 末尾有 `guard wantsDevelop else { … "press Solve
   to develop it" }`。`select()` 开头把 `wantsDevelop = false`,但打开路径里
   `recomputeFilmFormat` 等**会写 params**,而 `params.didSet` 会 `requestPrint()` ——
   于是**单张拖入会显影,点胶片条切帧不会**。
3. **画布把解码当成品。** 解码图被 `setLive` 当画面,角标只写 "preview",读起来像
   "这是你的成品(预览分辨率)"。实测 60 MP 帧:第一张成品 4.4 s,全分辨率再 4.8 s。

修法:

- **每一帧被选中就请求显影**(`select` 里 `wantsDevelop = true`):每帧都有胶片和相纸,
  所以每帧都该有成品。切帧仍有打印缓存兜底(先秒显旧片,再刷新)。
- **解码不再上画布**(`select` / 原生解码 / display-cache / decode 四处去掉 `setLive(解码)`)。
  解码仍然保留给「原图」和全分辨率渲染对齐用。
- 成品落地前画布是**空的中性底 + 角标「显影中…」**;成品落地即显示(成品在时不再重复
  显示 "preview")。
- **删除 Solve 按钮及其整行**(它证不出任何效果);`solveNow` 保留为程序化重解算。

**注意**:钉住旧策略的测试(`OpenPathTests.testTheCanvasDrawsTheNativeDecodeBeforeADevelop`
等)属于本机 39 个 **skipped**(缺相机 fixtures),所以这次行为改动**由抓图验证,不是由测试
验证** —— 那几条断言需要连同 fixtures 一起复审。

**负片→正片的仪式(2026-09-23,用户提的设计,已实现):**

继承原作者的"导入是底片、冲印才出片",但把它从**门槛**变成**第一张的仪式**:

- **引擎**:新增 `spk_preview_scan(session, tier, out)` —— 在**参数探测副本**上把
  `io.scan_film` 打开,复用缓存的负片、只跑印相阶段,返回后 session 原样恢复。
  之所以要新入口而不是直接切 `scan_film`:那个字段是**用户可见参数**(相纸列表里的
  「不使用相纸配置」),切它会让界面跟着跳。ctypes 验证:参数不变、之后的 reprint 与
  首印逐位相同、耗时 2.7 ms(负片命中缓存)。
- **动画的前提**:位置在**正在使用它的那次 draw 里**由 `CACurrentMediaTime()` 算出(没有中间量
  在累积,就不可能漂移);动画运行期间画布**自己续帧**(`needsDraw` → `scheduleDraw`)。画布仍然
  是"按需绘制",动画是唯一会自己索要帧的东西。`session` 只负责*什么时候*开始,`renderer` 负责
  *怎么动* —— 只有画布知道一帧什么时候在被画。**这一层从第一版起就没变过,
  变的全是"画什么"。**
- **动画的 brief(第五轮才说清的一句话)**:"光带一边扫过,被扫过的地方**同时显影**感觉才是
  对的,而且要慢一些,非线性的。" 前四版被否掉的不是"扫",是**实现与承诺不一致**:
  - 第一版一条硬边扫过(被扫过的地方直接就是正片);
  - 第二版给同一条边加了缓动和 0.8 s(还是"直接就是正片");
  - 第三版加了光带与相纸尾迹,但尾迹只有画面宽度 10%,而且**暗部**几乎瞬间到位;
  - 第四版把显影做成逐像素(暗部先出),可尾迹只有 **2%**,"被扫过的地方"依然等于"立刻是正片" ——
    所以观感一个字没变,而承诺的"同时显影"根本没有发生。
- **现在的机制**:一个 `develop`(0 = 负片、1 = 成品)驱动一切,**空间上的量只有光带的位置**:
  - 光带位置 `position = mix(-0.06, 1.70, develop)` —— 从画面左侧外进入、穿过、停在右侧外。
    之所以要**越过**右边:最后被扫到的那一条也要显影,而那发生在光带已经离场之后。
  - 光带**之前**:负片,原样。光带上:暖白的两宽度光带(紧核心 + 柔溢出),因为单个高斯读起来
    像模糊,不像灯。
  - 光带**之后**,先是**一条纯白的相纸**,**影像才开始长进去** —— 这两个事件是**故意不同步**的,
    这就是用户第三轮的原话"光带开始扫的时候相纸是白色的,扫过去一点以后白色才开始显影"。
    实现上是一个 `onset = 0.08`(光带后方仍有 8% 画面宽度是纯纸、一点影像都没有),之后才是
    逐像素的 `reach = mix(0.16, 0.50, 亮度)`:暗部在光带后约 24% 画面宽度内到密度,高光要 58%。
    **没有 `onset` 时密度和光同时到达**,尾迹多宽都一样会被读成"掀开";上一版的 2% 只是把这件事
    做到了极端。
  - **时长 3.6 s + septic ease(`35t⁴−84t⁵+70t⁶−20t⁷`,两端零速度、零加速度,起步比 smootherstep
    还平)**:十分之一时间处只走了 0.3%,四分之一处 7%(线性是 25%、`smoothstep` 16%、
    smootherstep 10%)—— 这是"非线性的感觉更明确"。
  - **时长为什么要一起加**:缓动越集中在两端,中段就越快,而"再慢一点"针对的正是中段那条扫过
    的速度。所以缓动加强的那部分由时长买单:**光带横穿仍然是 ~1.25 s**(和用户认可的 2.2 s 版
    一样的节奏),多出来的 1.4 s 全部是两端的停顿 —— 起步几乎不动的那一段,和光带离场后最后
    几条继续显影的那一段。只改 `printDevelopSeconds` 一个数就能整体再慢。
  - `u.develop` **为负表示画布上没有负片** —— "仪式在 0"和"根本没有仪式"必须是两张不同的图。
  - 走完时 `develop == 1`,算出来的就是 `c = printed` —— **和普通路径同一条采样表达式**,所以
    丢掉 `filmScan` 是**交接**而不是切一刀。曲线由 `testTheDevelopCurveIsNonLinear` 钉住
    (含"四分之一处 < 0.13"),交接由 `testTheDarkPartsOfThePrintComeUpFirst` 的末尾钉住。
- **这一版钉住的是"四个区域同时成立"**,因为那正是 brief 的结构:
  `RendererTests.testTheLightPassesAndThePrintDevelopsInItsWake` 在同一个 `develop` 上同时断言
  **光带之前是负片、光带处是光(附近最亮像素 > 0.95)、光带之后是纯白相纸(0.88…0.96,比光暗、
  比成品亮)、再往后是"已经显影但还在变"(0.6…0.88)**,最后才是成品。其中"纯白相纸"那一条还
  写成**关系**:`纸 > 尾迹` —— 用颜色调参满足不了它。
  `testTheDarkPartsOfThePrintComeUpFirst` 把**同一探针、同一距离**问两张不同密度的成品。
  - 写这条测试时踩到一次:光带最亮的那个像素在**接缝靠显影侧**,不在接缝上 —— 实测行是

- **抓图钩子 `--print S`**:快照路径自己会 `session.requestPrint()`,所以仪式**永远不会上膛** ——

  - **为什么 S 是"时刻"而不是"延迟"**:抓图里**根本没有实时 draw** —— 快照窗口用

新增 `menu*` / `set*` / `about*` 三组共 **121 个键**,两种语言都在表里 —— 那个 enum 没有 `default:`,
所以漏一个翻译是编译错误,不是窗口里的一块空白。

**为什么设置页以前只有一半是中文**:第一版只翻译了「语言」和「界面」两节,理由是"翻一半比整页都
不翻更难看"。这次按用户要求翻完,于是 `Diagnostics` 里那几句**坐在控件旁边的说明**
(`memoryReserveNote`、`memoryCapNote`、`diskCacheCapNote`、`perNodeTimingsNote`、
`logDirectoryNote`)和 `DiagnosticBundle.fileNamesNote` **从代码里删掉了** —— 一句文案两个家就是
会漂移的那个东西,现在它们和别的文案一样只有表里一份。`LogLevelSetting.label/detail` 同样搬进表里
(新增 `key`/`detailKey`,和 `AEMethod.key`/`FilmSide.key` 一个写法),`Diagnostics/LogCore.swift`
不再持有文案。

**检查更新去掉了**。它原来打的是上游项目的公开 release API
(`api.github.com/repos/JamesQiu2005/SpektraLab/releases/latest`)。用户的原话是"可以和原始 GitHub
项目断开了,几乎已经是不同的东西了" —— 于是 `Updates/UpdateCheck.swift`、它的测试和设置页
「本次会话」下面那一整块(按钮、状态、说明、打开 release 页)全部删除。**关于面板里的上游链接保留**:
那不是更新通道,是 CC BY-SA 要求的出处署名,和 GPL 的源码出处是两件事。

**新增抓图开关 `--settings`**:设置页是一个 `Window` 而不是 `Settings` scene(见
`SpektrafilmApp` 里那段注释:用 `Settings` scene 会让编辑窗口永远不出现),所以此前**没有任何**
抓图能拍到它 —— 这也是它底下半页能一直是英文的原因。`--settings` 渲染这一页,并且在
`snapshotMode` 下**去掉固定高度**,让 10 个分区一次全部出现在一张图里(真窗口是 640 pt 高的滚动栏,
一张截图最多只能看到前四节)。验证:中文一页到底、英文一页到底,各抓一张。
