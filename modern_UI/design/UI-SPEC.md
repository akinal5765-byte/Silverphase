# 界面规范 — Silverphase 主编辑器

一句话:这份文件定义界面的**结构、设计语言、组件行为、交互模型**。

**它是界面的最高权威。** 原始项目的参照图与 `TOKENS-main-v3-2026-09-18.md` /
`tokens-main-v3.json` 是**参考素材,不是规范** —— 它们描述上游产品的界面,我们不欠它
一致性。`Theme.swift` 是我们自己的 token 源,可以改,改了要同步 §2。

| 内容 | 唯一来源 |
|---|---|
| 信息架构、控件归属、组件行为、交互 | **本文件** |
| 颜色、字号、间距的当前取值 | `Theme.swift`(这里只写规则,不写数字) |
| SwiftUI 实现约束(用什么、不用什么) | `../UI-GUIDELINE-swiftui.md` |
| 中文文案与术语 | **本文件 §7** |
| 参照图(`../reference_layout/`) | 素材,可看不必遵守 |
| 本文与代码冲突 | **以本文为准**:规范是主张,代码是要被改的东西 |

## 1. 信息架构

### 1.1 区域

窗口分成六个区域,每个区域有且只有一类职责:

| 区域 | 只管 | 绝不放 |
|---|---|---|
| 菜单栏 | 帧级动作、视图状态、快捷键 | 影响渲染的数值 |
| 顶栏(工具栏) | 文件动作、视图状态、工具、两侧栏折叠 | 渲染参数 |
| 左栏(**预设**) | 胶片与相纸的选择(资源) | 参数微调、文件动作 |
| 画布 | 图像、只读叠加层、拾取类工具、直接操作 | 可编辑参数、一次性动作按钮 |
| 右栏(**参数**) | 影响渲染的参数 | 资源选择、文件动作 |
| 底栏(胶片条) | 选帧、单帧动作 | 参数 |
| 导出页 / 设置页 | 导出设置 / 应用偏好 | 单帧参数(只读回显可以) |

**用词先钉死**,不要再用"检查器"这个词:缩略图是**胶片条**(底栏),参数是**参数栏**
(右栏),胶片与相纸列表是**预设栏**(左栏)。

**布局与 Lightroom Classic 一致**:左预设、中画布、右参数、底胶片条。理由不是模仿,
是分工 —— 选一款胶片是"换一套配方",调一个滑杆是"改这套配方",两者是不同的动作,
放在不同的栏里,用户就不用在一个长栏里找东西。现在的代码把两者塞在同一个左栏,
这正是"按钮位置没有逻辑"的来源。

### 1.2 一个控件只有一个家

| 控件 | 归属 | 理由 |
|---|---|---|
| 胶片 / 相纸的选择(换配方) | 左栏(预设) | 这是"换一套",不是"改一处" |
| 滑杆、开关、下拉(改渲染) | 右栏(参数)对应分区 | 分区就是物理流程的一段 |
| 只读数值、状态徽章、直方图 | 画布叠加层(右上角) | 不是可操作的东西 |
| 分区级重置 | 该分区标题栏的 •••,文案写明作用范围 | 标题栏的动作作用于标题栏这一区 |
| 帧级重置、复制/粘贴设置 | 菜单栏 Frame | 跨分区的动作没有归属区 |
| 视图状态 | 顶栏;**菜单栏也有同一动作**,这是允许的例外 | 菜单是快捷键的可发现形式 |
| 解释性文字 | 该控件的 `.help(...)` | 不占版面 |

### 1.3 六条硬禁止

1. 同一控制不在两处(§1.2 最后一行除外)。
2. 画布上不放可编辑控件,也不放一次性动作按钮。
3. 文案里不写死配置名或 ID。
4. 新控件不许用 token 之外的字面量。
5. 不许有"只在默认值下才存在"的控件:任何会被持久化的设置都要能被找到、能改回。
6. 不许出现没有原因的禁用态。

### 1.4 骨架

```
┌──────────────┬──────────────────────────────┬──────────────┐
│ 顶栏  打开·导出 │   缩放 · 适合 · 对比 · 全屏     │ 叠加层 · 折叠 │
├──────────────┼──────────────────────────────┼──────────────┤
│ 预设栏(左)    │  画布                          │ 参数栏(右)    │
│  胶片列表      │   右上角: 直方图(只读)          │  输入 / 相机  │
│  相纸列表      │   其下:   徽章                 │  胶片         │
│              │                              │  显影         │
│              │                              │  印相         │
│              │                              │  裁剪         │
├──────────────┴──────────────────────────────┴──────────────┤
│ 胶片条                                                       │
└────────────────────────────────────────────────────────────┘
```

分区内容(每个参数只有一个家,全部在**右栏**):

| 分区 | 内容 |
|---|---|
| 输入 / 相机 | 测光方式、胶片曝光、白平衡(色温 / 色调)、镜头校正 |
| 胶片 | 胶片画幅(类型 / 基准边 / 边长)、颗粒、胶片晕光(档位 + 晕光强度) |
| 显影 | 显影反差、色彩分离 |
| 印相 | 印相曝光、黄色滤光、品红滤光、预闪、印相眩光、扩展动态范围、不使用相纸配置 |
| 裁剪 | 宽高比、拉直、旋转、翻转 |

**左栏只有选择,没有数值**:两款列表(胶片、相纸)属于左栏;选中之后这款胶片的**参数**
属于右栏。同一个胶片既在左栏(被选中)又在右栏(参数)出现是正常的 —— 那是两个不同的
动作,不是"同一控制两处"。

**放大机区删除**(不只是 flag 关掉):印相曝光与黄/品红已经在「印相」区有家。
将来若要暴露光源,它是「印相」区里的一行,不是新分区。

## 2. 设计语言与材质

### 2.1 密度与节奏

- 一个控件一行。行高、控件高、行间距一律取 `Theme.Metric`,不在 View 里写数字。
- 分区内行与行**等距**;分区之间靠 hairline + `sectionBottom` 分隔。
- 参数区的目标是"一屏读完一个分区",不是"每行都很大"。宁可行短、间距准。
- **不给控件加内边距来"透气"**;透气靠行间距。控件高就是控件高。

### 2.2 表面:只有五层

一个表面 = **填充 + 内描边 + 顶部高光 +(可选)落影 + 圆角**。层次只由这五件事表达,
不由边框粗细表达。

| 层 | 名称 | 用在哪 | 圆角 |
|---|---|---|---|
| L0 | ground | 窗口底 | 0 |
| L1 | card | 两侧栏、胶片条 | 0 |
| L2 | well | 列表、直方图的凹槽 | 小 |
| L3 | control | 药丸、字段、按钮、滑杆轨道 | 控件圆角 |
| L4 | overlay | 画布叠加层、菜单 | 只有这层可有较大圆角与落影 |

规则:

- 每层比它下面一层亮或暗**一个固定步长**;步长写进 `Theme`,不在 View 里调。
- 每个表面有一条 **1px 内描边:上半亮(白 6–10%)、下半暗(黑 15–25%)**。
  这一条是"质感"的主要来源 —— 没有它,控件就是一张色块。
- **L0–L3 一律不投影。** 落影只属于 L4。
- 填充允许极淡的垂直渐变(顶亮约 2%),不允许纹理、不允许玻璃拟态。

`Theme` 需要为此新增一组 token(第 1 期做):内描边的上下两色、hover / pressed 的填充、
轨道的两段色、滑块描边与落影、L4 落影。**这些值只存在于 `Theme`,View 里不许出现数字或即席色。**

### 2.3 控件的状态

药丸 / 字段 / 按钮统一三层:填充、内描边、内容。状态做法固定:

| 状态 | 做法 |
|---|---|
| default | 填充 + 上亮下暗内描边 |
| hover | 填充提亮约 6%;内描边同步提亮 |
| pressed | 填充压暗约 4%;内描边**翻转**(上暗下亮),产生"按下去"的错觉 |
| focus | 外圈 2px accent + 1px 间隙;**不改变填充** |
| disabled | 整体 38% 不透明度,但**保留内描边**(不能塌成半个控件);必须能说出原因 |
| selected | 见 §2.4 |

### 2.4 列表与选中

- 列表坐在 **well** 里,不是坐在 card 上。
- 选中 = 白色胶囊 + 1px 暗描边 + 极淡落影 + `onSelection` 文字;胶囊比行窄 2pt,不顶到边。
- hover = 淡填充(白 4–6%);**不加描边、不位移、不缩放**。

### 2.5 滑杆

- 轨道高约 3pt、全圆角;未过部分用暗版 rule,**已过部分用亮版 rule** —— 不用 accent,
  accent 只留给真正的"看这里"。
- 滑块直径约 9pt:1px 亮描边 + 1px 落影。hover 时**滑块不变大**,轨道提亮。
- 数值药丸固定宽度、等宽数字、右对齐。
- 拖动中:已过轨道与滑块同时提亮一档,数值药丸反白。

### 2.6 分隔与文字

- hairline:1px、**白 8%**。纯色线看起来像画上去的。
- 分区之间用 hairline;**行与行之间不用线**,用间距。
- 文字三级 `text / secondaryText / dim`;中文走系统中文回退,保持粗体语义。
- 数值一律 `monospacedDigit` + 右对齐;单位属于标签,不属于数值。

### 2.7 字体阶梯

只有四档,不新增:

| 档 | 用途 |
|---|---|
| 分区标题 | 区名 |
| 正文 | 胶片区的标签、列表分组标题 |
| 小号 | 相机区的标签、所有控件值 |
| 等宽数字 | 一切会变化的数值(缩放、EV、百分比) |

中文与英文配置名混排时**不要为了塞进去而降字号**;调整标签列宽。

### 2.8 图标

- 一律 SF Symbols,统一 weight;只有两档尺寸(栏头 / 行内)。
- 与相邻文字**光学对齐**,不是按字号框对齐。
- 纯图标按钮命中区 26×26,必须有 `.help(...)`。
- 图标不表达状态;状态用颜色、文字或位置。

### 2.9 画布叠加层

画布上的东西是**画在照片上**的,不是浮在照片上的卡片:

- 它属于 L4,但**只允许落影,不允许底板颜色、圆角、内边距**。
- 可读性靠一层极淡的顶部渐变压暗(约 12% → 透明),不靠一块灰。
- 直方图固定在**右上角**,徽章在其下方,共用一条纵向间距规则。
- 叠加层可开可关,顶栏给开关,状态持久化,默认开。
- 叠加层不拦截拖动;除拾取类工具外,画布上的点击都属于画布。

### 2.10 什么会显得廉价(禁止)

| 禁止 | 改成 |
|---|---|
| 用纯色 1px 边框勾控件 | 上亮下暗的内描边 |
| 每层都加圆角和投影 | 投影只给 L4 |
| hover 时位移、放大、抖动 | 只改填充与描边 |
| accent 到处用 | accent 一次只在一处 |

**accent 的定义(2026-09-23,用户要求)**:`Theme.accent` = **Apple 橙 `#FF9F0A`**
(`NSColor.systemOrange` 的深色外观取值;浅色版是 `#FF9500`)。理由就是 accent 唯一的
工作是"被认出来",而人认得的橙是系统那个 —— 它替掉了 v3 图纸采样出来的 `#E1A95F`
(一个土黄)和更早的 `#ee8a2b`。写成字面值而不是 `Color(nsColor: .systemOrange)`,
是为了不让界面在系统外观/辅助功能设置/OS 更新下移动。

**而且它不再渐变** —— 同一句要求的下半段:"橙色不需要渐变了,这样显得更专业"。顶光
(`pillSurface(wash:)`)是**灰色材质**用来表示"这是一块浮起来的表面";放在整个界面唯一
用来当**信号**的颜色上,它读起来就成了一个亮面按钮,而信号本身就是全部意义。所以:
- `pillSurface(base:wash:)` 新增 `wash`;accent 板一律 `wash: false`
  (主按钮 `SurfaceButton`、导出页主按钮、导出页命名 chips)。
- `ScrubSlider` 的复选框原来在选中时是 `accent → accent.opacity(0.80)` 的渐变,
  现在是纯 accent。
- **1px 描边留着**:那是材质的边,不是橙色。
- 不属于这一条的橙色有两处,都是**照片的东西而不是界面**:擦除动画里那盏暖色灯
  (`Shaders.metal` 里的 `float3(1.0, 0.87, 0.64)`)和底片本身的橙色罩(引擎的物理),
  以及白平衡轨道的 `#FFF100` 端点(那是**色标**,不是装饰)。
| 数值用比例字体(会左右跳) | 等宽数字 |
| `Color.gray` / `.black.opacity()` 这类即席色 | `Theme` token |
| 系统材质 / 玻璃拟态 / 毛玻璃 | 五层表面 |
| 一张图里出现两种圆角 | 一种控件圆角 |
| 大图标、插图、吉祥物式空态 | 一句话 + 一个动作 |

### 2.11 动效

以 §6 为准。摘要:hover 约 100ms、按下即时、面板折叠约 180ms;**数值变化不动画**。

## 3. 组件规范

每个组件必须写清**结构 / 状态 / 交互**三件事。状态至少包含
default、hover、active、focus、disabled 五种;缺哪个要有理由。

### 3.1 滑杆(参数的主力)

- 结构:标签列 | 轨道 | 数值药丸。单位与方向写在标签的第二行,不写进数值。
- 交互:
  - 拖动轨道:改值,按 `snap` 吸附。
  - 拖动**标签**:同样改值(scrub),这是老手的路径。
  - 双击标签或数值:回到该参数的默认值(`zero` 或默认档)。
  - 单击数值:进入输入,回车提交,Esc 取消,非法输入回弹并提示。
  - 键盘:聚焦后方向键 ±1 步,⇧ 方向键 ±10 步。
- 状态:hover 时轨道提亮一档;active 时数值药丸反白;focus 时有一致的焦点环;
  disabled 时必须能通过 tooltip 说出原因。
- 拖动整段只算**一次撤销**。

### 3.2 下拉药丸

- 结构:标签 | 药丸(当前值 + 折角)。
- 交互:点击展开;菜单项当前项带勾;上下键选择,回车确认,Esc 关闭。
- 值多到超过 5 个时,考虑换成带搜索的菜单,而不是更长的列表。

### 3.3 开关行

- 整行可点,不是只有开关可点。
- 关掉一个开关时,**它管辖的从属控件一起置灰**,并保留在原位(不塌陷、不消失)。

### 3.4 分组列表(胶片 / 相纸)

- 正面/负面、静态摄影/电影是分组标题,不是可选项,不参与键盘选择。
- 选中用白胶囊 + 深色字;hover 用淡底;键盘上下移动选择,回车确认。
- 列表本身可滚动,滚动条不常显;分组标题吸顶。

### 3.5 数值字段

- 可输入。非法值不静默接受:回弹 + 说明。
- 单位属于标签,不属于输入框;输入框里只有数字。

### 3.6 按钮四级

| 级别 | 用途 | 出现位置 |
|---|---|---|
| 主按钮 | 一屏一个,推进流程(自动测光与配光) | 分区底部 |
| 次按钮 | 重置、次要动作 | 分区底部或标题栏 ••• |
| 图标按钮 | 视图类、工具类,有 tooltip | 顶栏、栏头 |
| 危险按钮 | 删除类 | 菜单内,或带确认 |

同一屏不出现两个主按钮。

### 3.7 分区头

- 结构:展开三角 | 标题 | (可选)•••。
- 整行可点开关;••• 里的动作必须与分区同域,并写明作用范围。
- 展开/收起状态属于用户偏好,持久化。

### 3.8 空态

- 一句中文说清"这里为什么是空的",加一个动作(如胶片条:按 ⌘O)。
- 空态不用插图、不用大图标。

## 4. 交互模型

### 4.1 鼠标与修饰键

| 操作 | 结果 |
|---|---|
| 拖动滑杆标签 | 调值(scrub) |
| 双击标签 / 数值 | 复位到默认 |
| ⇧ + 拖动 / 方向键 | 精调(10× 更细 / ±10 步) |
| ⌥ + 拖动 | 减速,便于精确定位 |
| 右键 | 上下文菜单(画布、列表、参数行) |
| 滚轮 / 触控板 | 画布缩放(以指针为中心);列表滚动 |

**同一个操作在所有同类控件上行为一致。** 一个滑杆能双击复位,所有滑杆都要能。

### 4.2 画布

| 操作 | 结果 |
|---|---|
| 拖动 | 平移(空间键按住 = 临时平移工具) |
| 滚轮 / 双指 | 以指针为锚缩放 |
| 双击 | 在"适合窗口"与 100% 之间切换 |
| 对比模式 | 拖动分界线;Y 键切换 |
| 白平衡吸管 | 按下拾取、松开应用;Esc 取消;拾取时显示放大镜 |
| 裁剪 | 八向手柄 + 三分线;回车提交,Esc 取消 |

### 4.3 键盘

- Tab 能在参数栏里走完所有可交互控件;焦点环统一。
- 分区可用快捷键折叠/展开,但快捷键不写进译文。
- 所有菜单动作都有快捷键,并且**菜单栏与顶栏是同一动作的两个入口**,不是两套实现。

### 4.4 撤销

- 每一次参数改动入栈;⌘Z / ⇧⌘Z。
- 一次拖动、一次输入提交 = 一次撤销,不是每帧一次。
- 视图状态(缩放、面板折叠、叠加层开关)不进撤销栈。

### 4.5 工具提示

- 统一延迟出现,内容包含:它是什么、单位、范围、以及禁用原因(若禁用)。
- 提示文字也算用户可见文案,必须走本地化(§7)。

## 5. 状态与反馈

### 5.1 四种状态,每种都有出口

| 状态 | 表现 | 出口 |
|---|---|---|
| 空 | 一句话 + 一个动作 | 该动作 |
| 忙 | 进度指示 + 可取消 | 取消键 |
| 禁用 | 变灰 + 原因 tooltip | 说明如何解除 |
| 错误 | 一句人话 + 一个可执行动作 | 重试 / 打开位置 |

**不允许出现"看起来能用但没反应"的控件**,也不允许"变灰但不说为什么"。

### 5.2 渲染与加载

- 渲染中:画布角上给状态,不用全屏遮罩。
- 提高分辨率时保留上一张画面,不要闪成空白。
- 超过约 1 秒的阻塞必须能看到反馈。

### 5.3 错误

- 不把系统错误直接抛给用户;包装成"发生了什么 + 怎么办"。
- 不弹模态对话框处理可恢复错误。

## 6. 动效

- 只有三处动画,时长统一:面板折叠(~180ms ease-out)、悬停反馈(即时)、值变化(不闪)。
- **值变化不做动画**:数值等宽,原处刷新。
- 禁止弹跳、缩放、旋转类装饰动画。
- 尊重系统"减弱动态效果"设置。

**「打开即显影」的策略修正(2026-09-23,用户报"拖入照片看到的还是原图,点按钮才出片"):**

查到底后的三条事实:

1. **那个按钮是空的。** ctypes 探针比较"打开后"与"`solve(both)` 后":所有参数一个没变
   (中性滤光值/印相曝光在打开时就是解算值),**像素逐位相同**(0 / 110592 采样点变化)。
   测光在打开时已跑,中性滤光值在 `digest` 里由数据库写入。所以它唯一的效果是**触发重画**。
2. **开发是有门的,而且门不稳定。** `load` 末尾有 `guard wantsDevelop else { … "press Solve
   to develop it" }`。`select()` 开头把 `wantsDevelop = false`,但打开路径里
   `recomputeFilmFormat` 等**会写 params**,而 `params.didSet` 会 `requestPrint()` ——
   于是**单张拖入会显影,点胶片条切帧不会**。
3. **画布把解码当成品。** 解码图被 `setLive` 当画面,角标只写 "preview",读起来像
   "这是你的成品(预览分辨率)"。实测 60 MP 帧:第一张成品 4.4 s,全分辨率再 4.8 s。

修法:

- **每一帧被选中就请求显影**(`select` 里 `wantsDevelop = true`):每帧都有胶片和相纸,
  所以每帧都该有成品。切帧仍有打印缓存兜底(先秒显旧片,再刷新)。
- **解码不再上画布**(`select` / 原生解码 / display-cache / decode 四处去掉 `setLive(解码)`)。
  解码仍然保留给「原图」和全分辨率渲染对齐用。
- 成品落地前画布是**空的中性底 + 角标「显影中…」**;成品落地即显示(成品在时不再重复
  显示 "preview")。
- **删除 Solve 按钮及其整行**(它证不出任何效果);`solveNow` 保留为程序化重解算。

**注意**:钉住旧策略的测试(`OpenPathTests.testTheCanvasDrawsTheNativeDecodeBeforeADevelop`
等)属于本机 39 个 **skipped**(缺相机 fixtures),所以这次行为改动**由抓图验证,不是由测试
验证** —— 那几条断言需要连同 fixtures 一起复审。

**负片→正片的仪式(2026-09-23,用户提的设计,已实现):**

继承原作者的"导入是底片、冲印才出片",但把它从**门槛**变成**第一张的仪式**:

- **引擎**:新增 `spk_preview_scan(session, tier, out)` —— 在**参数探测副本**上把
  `io.scan_film` 打开,复用缓存的负片、只跑印相阶段,返回后 session 原样恢复。
  之所以要新入口而不是直接切 `scan_film`:那个字段是**用户可见参数**(相纸列表里的
  「不使用相纸配置」),切它会让界面跟着跳。ctypes 验证:参数不变、之后的 reprint 与
  首印逐位相同、耗时 2.7 ms(负片命中缓存)。
- **动画的前提**:位置在**正在使用它的那次 draw 里**由 `CACurrentMediaTime()` 算出(没有中间量
  在累积,就不可能漂移);动画运行期间画布**自己续帧**(`needsDraw` → `scheduleDraw`)。画布仍然
  是"按需绘制",动画是唯一会自己索要帧的东西。`session` 只负责*什么时候*开始,`renderer` 负责
  *怎么动* —— 只有画布知道一帧什么时候在被画。**这一层从第一版起就没变过,
  变的全是"画什么"。**
- **动画的 brief(第五轮才说清的一句话)**:"光带一边扫过,被扫过的地方**同时显影**感觉才是
  对的,而且要慢一些,非线性的。" 前四版被否掉的不是"扫",是**实现与承诺不一致**:
  - 第一版一条硬边扫过(被扫过的地方直接就是正片);
  - 第二版给同一条边加了缓动和 0.8 s(还是"直接就是正片");
  - 第三版加了光带与相纸尾迹,但尾迹只有画面宽度 10%,而且**暗部**几乎瞬间到位;
  - 第四版把显影做成逐像素(暗部先出),可尾迹只有 **2%**,"被扫过的地方"依然等于"立刻是正片" ——
    所以观感一个字没变,而承诺的"同时显影"根本没有发生。
- **现在的机制**:一个 `develop`(0 = 负片、1 = 成品)驱动一切,**空间上的量只有光带的位置**:
  - 光带位置 `position = mix(-0.06, 1.70, develop)` —— 从画面左侧外进入、穿过、停在右侧外。
    之所以要**越过**右边:最后被扫到的那一条也要显影,而那发生在光带已经离场之后。
  - 光带**之前**:负片,原样。光带上:暖白的两宽度光带(紧核心 + 柔溢出),因为单个高斯读起来
    像模糊,不像灯。
  - 光带**之后**,先是**一条纯白的相纸**,**影像才开始长进去** —— 这两个事件是**故意不同步**的,
    这就是用户第三轮的原话"光带开始扫的时候相纸是白色的,扫过去一点以后白色才开始显影"。
    实现上是一个 `onset = 0.08`(光带后方仍有 8% 画面宽度是纯纸、一点影像都没有),之后才是
    逐像素的 `reach = mix(0.16, 0.50, 亮度)`:暗部在光带后约 24% 画面宽度内到密度,高光要 58%。
    **没有 `onset` 时密度和光同时到达**,尾迹多宽都一样会被读成"掀开";上一版的 2% 只是把这件事
    做到了极端。
  - **时长 3.6 s + septic ease(`35t⁴−84t⁵+70t⁶−20t⁷`,两端零速度、零加速度,起步比 smootherstep
    还平)**:十分之一时间处只走了 0.3%,四分之一处 7%(线性是 25%、`smoothstep` 16%、
    smootherstep 10%)—— 这是"非线性的感觉更明确"。
  - **时长为什么要一起加**:缓动越集中在两端,中段就越快,而"再慢一点"针对的正是中段那条扫过
    的速度。所以缓动加强的那部分由时长买单:**光带横穿仍然是 ~1.25 s**(和用户认可的 2.2 s 版
    一样的节奏),多出来的 1.4 s 全部是两端的停顿 —— 起步几乎不动的那一段,和光带离场后最后
    几条继续显影的那一段。只改 `printDevelopSeconds` 一个数就能整体再慢。
  - `u.develop` **为负表示画布上没有负片** —— "仪式在 0"和"根本没有仪式"必须是两张不同的图。
  - 走完时 `develop == 1`,算出来的就是 `c = printed` —— **和普通路径同一条采样表达式**,所以
    丢掉 `filmScan` 是**交接**而不是切一刀。曲线由 `testTheDevelopCurveIsNonLinear` 钉住
    (含"四分之一处 < 0.13"),交接由 `testTheDarkPartsOfThePrintComeUpFirst` 的末尾钉住。
- **这一版钉住的是"四个区域同时成立"**,因为那正是 brief 的结构:
  `RendererTests.testTheLightPassesAndThePrintDevelopsInItsWake` 在同一个 `develop` 上同时断言
  **光带之前是负片、光带处是光(附近最亮像素 > 0.95)、光带之后是纯白相纸(0.88…0.96,比光暗、
  比成品亮)、再往后是"已经显影但还在变"(0.6…0.88)**,最后才是成品。其中"纯白相纸"那一条还
  写成**关系**:`纸 > 尾迹` —— 用颜色调参满足不了它。
  `testTheDarkPartsOfThePrintComeUpFirst` 把**同一探针、同一距离**问两张不同密度的成品。
  - 写这条测试时踩到一次:光带最亮的那个像素在**接缝靠显影侧**,不在接缝上 —— 实测行是
    `0.50 … 0.74 0.80 0.86 0.95 1.00 | 0.56 0.08 0.02 0`(接缝那一格属于负片侧,只有光)。
    断言改成取附近五像素的**最大值**,不猜具体坐标:接缝落在像素之间,落在哪一侧不是这条断言
    要问的事。**先把这一行打出来再写断言,比推算半天快。**
- **抓图钩子 `--print S`**:快照路径自己会 `session.requestPrint()`,所以仪式**永远不会上膛** ——
  也就是说这个产品开场唯一的动画,恰好是抓图工具照不到的那个。`--print S` 等到负片在位后点击
  「冲印」,再抓 S 秒处的帧。
  - **为什么 S 是"时刻"而不是"延迟"**:抓图里**根本没有实时 draw** —— 快照窗口用
    `SnapshotCanvas` 顶替 Metal 视图,日志实测整场抓图 `draw(in:)` 一次都没跑,所以

  - 推进走的是 `Renderer.applyDevelop(elapsed:)` —— **动画自己用的同一条曲线**,不是抓图工具

  - 失败模式是诚实的:负片没到位 → `printNegative` 是个空操作 → 抓到的是成品,而不是一张
    假的动画帧。`S = 3.6`(走完)就是成品,可当对照。
  - 抓图验证(33 MP ARW、1400×900 窗口,1:1 裁切):0.9 s(t=0.25)光带只走了画面 12%,
    起步几乎不动;1.8 s(t=0.5)光带在画面 82% 处,**它左边依次是纯白相纸 → 正在显影的影像 →
    已经到位的成品,右边是负片**;2.6 s 光带已离场、右侧最后几条还在收;3.6 s 是干净的成品。
  - 顺带一个一致性检查:3.0 s 版的 1.5 s 与 3.6 s 版的 1.8 s 都是 `develop = 0.5`,抓图
    **逐字节相同** —— 说明画面只由 `develop` 决定,改时长/缓动不会改画什么。

- **成品缓存不能吃掉仪式(2026-09-23 修)**。用户报:"多图导入之后第一张图没有新的动画和负片,

  消耗的(负片还要引擎持有这一帧才能 `spk_preview_scan`,而成品缓存存在的意义就是**绕开引擎**)。

## 应用图标(2026-09-23,Silverphase)

概念图是两卷叠在一起的胶片:后面一卷银色、偏左上,前面一卷橙色、偏右下。实现是
`Spektrafilm/Silverphase.icon` —— 一个 **Icon Composer 文档**(`icon.json` + `Assets/*.svg`),
由 `Tools/make-icon.py` 从一组参数画出两条素材。

**为什么是文档而不是一张 PNG**:macOS 26 起图标的最终样子由系统合成 —— 圆角外壳(遮罩)、
Liquid Glass 的高光与折射、阴影都是系统加的。往 SVG 里烤一层高光,屏幕上就会有两层;所以
素材里**只有材质**:

- **背景**:文档的 `fill` 是一条很浅的渐变(白 → 冷灰)。**dark 外观不写 specialization** ——
  系统自己给深色底,这正是"玻璃由 Apple 自动添加"的同一件事:浅色/深色两种底座都是系统的。
- **两条胶片**:各自一个 **group**(各自一份玻璃与阴影,前面那卷的影子才会落在后面那卷上),
  `glass: true`、`lighting: individual`、`blur-material 0.4`、轻微 `translucency`,
  前面那卷多一个 `refractivity`(要在文档顶部声明 `features: ["refractivity"]`)。
- **齿孔是孔,不是白点**:一条 `fill-rule="evenodd"` 的 path 把外框和 12 个孔放在一起,
  所以背景和玻璃会从孔里透出来。**画格窗是面板**(胶片透明的片基),画在上面。
- **齿孔每边 6 个,不是 35 mm 的 9 个**:16 pt 下 9 个只会连成一条虚线。

**第四个踩到的点,而且它是"图标没换"的元凶**:上一个产品名留下的 `SpektraLab.icns` 不在源码树里、
也不在 `git ls-files` 里,而在**构建中间产物** `DerivedData/…/assetcatalog_output/thinned/`(时间戳
14:09,改名之前那次构建)。actool 的增量构建会把整个 thinned 目录**复制**进 bundle,**连时间戳一起**
—— 所以只从 bundle 里删掉它没用,下一次构建它又回来了,`Contents/Resources/` 里就一直是
"新图标 + 一个旧的 `.icns`"。删要删中间产物那份(或 clean)。**判断"跑的是哪一版"仍然看时间戳**,
但看的是 `Assets.car` 和 `Silverphase.icns` 的,不是"有没有 `SpektraLab.icns`"。

**三个踩到的点,都记在这儿**:

1. **`groups` 的顺序是"前 → 后"**(和 Icon Composer 的图层列表一样,第一行在最前面)。
   把橙色那卷写在前面才压在银色上面 —— 先写银色时渲染出来是反的。
2. **`color-space-for-untagged-svg-colors` 只接受 `display-p3`**(这个 Icon Composer 构建
   会拒收 `srgb`,报 "The data couldn't be read because it isn't in the correct format")。
   于是 SVG 里没标色的十六进制会被当成 **P3 数值**读,而设计是在 sRGB 里选的 —— 直接把 sRGB
   的十六进制写进去,屏幕上每个颜色都会比设计的更艳。所以 `make-icon.py` 把 sRGB 经过
   线性光 + CSS Color 4 的矩阵转成 P3 数值再写文件:sRGB `#FF9F0A`(界面的 accent)
   落到 P3 的 `#F2A33C`,是同一个橙色。
3. **`position` 必须同时给 `scale` 和 `translation-in-points`**,只给 scale 会让 Icon Composer
   打不开文档(而旧 schema 会放它过)。

**"透明叠加"是怎么做出来的(用户三次反馈,从"上面黄的把下面灰的覆盖了"到最后一次"和之前一样",
参照官方照片 App 那朵花瓣)** —— 五件事,每一件都是我一开始做错的:

0. **"透过来"是材质的事,不是把 `glass` 关掉。** 这一条我前后搞错了两次,最后按用户的提醒回去读规范
   才做对:玻璃的**透射**由**组**上的 `translucency` 控制(UI 里叫 Translucency,"content behind
   the glass shows through"),`blur-material` 控制它透过来时**糊不糊**,`refractivity` 是边缘那层
   折射/放大(照片 App 花瓣边上的"透镜"),`specular` 是highlight。正确的组合是:

   | 键 | 值 | 作用 |
   |---|---|---|
   | 层 `glass` | **true**(两卷都开) | 这一层参与 Liquid Glass |
   | 组 `translucency` | 前卷 **0.60**(dark 外观 0.40) | 后面那卷透过来多少 |
   | 组 `blur-material` | 前卷 **0** | 0 = 透过来是**清晰**的胶片,不是磨砂玻璃 |
   | 组 `refractivity` | `{enabled, strength 0.35, depth 0.30}` | 边缘的透镜感 |
   | 组 `lighting` | `individual` | 每层各自受光 |
   | 素材 alpha | 前卷 **0.96**(窗 0.70) | **只管颜色**,不要拿它当透射 |

   - **我错在哪**:先用整卷 alpha 0.60/0.68/0.75 去做透射 —— 结果是橙色被冲成奶白,而
     透明度并没读出来;然后干脆把前面那卷的 `glass` 关掉(那一版**确实**透,但**没有玻璃质感**,
     用户的反馈:"透是透了,但是没有玻璃质感")。**材质开着才对**,alpha 交给材质。
   - **实测颜色**(白底,以 sRGB 读):`#F89D13` —— Apple 橙是 `#FF9F0A`,差 2/2/9,已是同一条橙。
   - **dark 外观必须单独给 `translucency`**(`translucency-specializations`,整个对象替换):
     0.75 的透射在近黑底上会把橙卷压成褐色;dark 用 0.40,灰卷依然透得出来。
   - **透射也不能给太多**:0.75 + refractivity 0.5 在 1024 尺寸下会把橙卷下半段冲成奶白
     (白底从那里透上来),最后落在 **0.60 / 0.35** —— 橙卷保住自己的橙,灰卷照样透得出来。
     这两个数就是最后的旋钮。
1. **"透明"也可以是形状上的开口。** 这是最后一层、也是最关键的一层:把画格窗
   做成 alpha 很低的**填充**(0.18)时,系统仍然把它**填成一块玻璃** —— 于是"透过去"看起来只是
   "变淡",而不是"看见后面那卷"。只有把窗做成**真正的开口**(和齿孔一样进 `evenodd` 那条 path,
   那里根本没有面积),后面那卷才会 **100% 透出来**。所以现在:**橙卷的边框是不透明的 Apple 橙,
   画格窗是三个洞**;银卷的窗仍是浅灰面板(胶片片基),孔也是洞。这也是物理上对的 ——
   画格窗本来就是片基露出来的地方。
2. **每一卷是"半透明的彩色形状",不是"不透明的形状加一层雾"**。花瓣那种观感 =
   颜色本身带 alpha(底色上偏粉彩、两个形状交叠处变深),而不是把整组的 `translucency` 拉高
   —— 后者只会把橙色冲成奶白(试过 0.6/0.75/0.9,一路变浑浊)。现在素材最外层是一个
   `<g opacity>`(前面那卷 0.96、后面 0.94)。**整卷压到 0.68 会把橙色冲成奶白** —— 0.60/0.68/0.75
   三档都试过,越透越不像 Apple 橙;所以 alpha 只留一点点材料感,"透"交给第 0 条的开口。
   - **实测**:`<g opacity="0.68">` 与 `opacity="1.00"` 两张渲染 psnr 28.65 —— 组的 `opacity`
     是被认的;而最初把 alpha 写在渐变路径的 `fill-opacity` 上,画面上**看不出任何变化**,
     所以现在一律写在组和渐变的 `stop-opacity` 上。
3. **后面那卷必须是一块灰板,不是"白底加灰框"**。一开始银色那卷的窗是接近白的(#E8EDF4),
   于是前面那卷底下几乎全是亮的 —— **没有东西可以透**。概念图里灰卷是一整块灰、只有齿孔是
   白的,所以现在银色卷的窗只比片身亮一点点(#B4BFCB 对 #C2CAD6→#7C8797),齿孔仍然是真孔。
   这时候橙色压过去才会明显地变灰、变深,而齿孔透出来是亮点。
4. **两卷要错开**(见上):窗对窗互相抵消。竖直方向错开接近一个画格间距,前面的窗落在后面的
   片身/齿孔上,叠加才读得出来。

**`blend-mode` 在 Liquid Glass 层上是失效的**:去掉前面那层的 `blend-mode: "multiply"` 再渲染,
PNG **逐位相同**(psnr = inf),所以那个键已经从文档里删掉,不留一个看起来在起作用的东西。

**验证**:`ictool`(在 `Icon Composer.app/Contents/Executables/`,注意**不是**
`Developer/usr/bin/ictool`,那是另一个同名工具)渲染 Default/Dark/128 pt 三个 rendition 看效果;
然后构建 app,`Assets.car` + `Silverphase.icns` 进包,再用 `Tools/render-icon.swift` 按 Finder

### 定案:一卷胶片 = **片基 + 画框**(2026-09-23,最后一版)

用户第三次反馈:"这个透的不太对吧"。这一次不是缓存,是我的模型错了 —— 我把"透"整个交给
**材质透射**,于是白底也从每一处透上来,橙卷下半段被冲成奶白(材质还把灰卷的窗糊成一块)。
物理上没错(半透明的橙色滤片压在白纸上就是发白),但**那不是胶片的样子**。

**一卷胶片其实是两样东西**,现在按这个做:

- **画框**(`2-orange-strip.svg`,层名 "Orange frame",`glass: true`):不透明的 Apple 橙,
  齿孔是孔、**画格窗是开口**。材质给它边缘高光与折射 —— 这是用户要的"玻璃质感"。
- **片基**(`2-orange-strip-base.svg`,层名 "Clear base",`glass: false`):三个画格窗大小的
  **浅橙**块(`#FFB84D`,`opacity 0.55`),画在框后面。它把透过去的灰卷染成胶片的颜色,
  于是窗读起来是"片基"而不是"框上挖的洞"(用户否掉过那个:为什么橙色只剩下外框了)。

于是组上的 `translucency` 不再承担"透",退回**0.25**(dark 0.20)只留一点材料感;
`blur-material: 0` 让透过去的东西保持清晰;`refractivity 0.35/0.30` 是窗边的透镜。

**实测(sRGB,白底)**:框 `#FC9C0A` / `#F19313` —— Apple 橙是 `#FF9F0A`,同一条橙;
窗内(灰卷处) `#F2CC92`,灰卷的身、窗、孔都还看得见。

**两个旋钮**:`Tools/make-icon.py` 里 `ORANGE` 的 `base`/`base_alpha`(片基的颜色与浓度)
与 `icon.json` 里那组的 `translucency`。用户最后定的是 `base_alpha = 0.75`
(0.55 偏淡、0.90 层次没了;窗内实测 `#F8C374`,画框 `#FC9C0A`)。

**图标缓存有两层,杀 agent 不够**:`iconservicesagent` 的**按路径**缓存之外,磁盘上还有
`~/Library/Caches/com.apple.iconservices.store` 与 `/private/var/folders/<...>/C/com.apple.iconservicesagent`。
只 `killall iconservicesagent` 时,重启后的 agent 会把这些 store 读回来,**同一个路径仍然给你几轮前的图**
(用户的 Finder"简介"预览和 Dock 都是这样)。要真刷新:删掉上面两处 store + `killall iconservicesagent`
+ `touch` bundle 目录 + `lsregister -f`,然后重开"简介"窗口。
另外 **bundle 的"修改时间"不会因为里面文件被重写而变**(只有增删文件才变),所以 Finder 显示
"修改时间 22:39"而 `Assets.car` 是 23:01 是正常的 —— 判据看 `Assets.car`/`Silverphase.icns` 的
时间戳,或者把 app `ditto` 到一个新路径读回。

### 深色底是**系统设置**,不是"深色模式"带来的

用户问"按理说符合规范的图标是不是可以变成深色底?" —— 可以,但 macOS 26 里**图标的深色底是一个
独立的设置项**,和"浅色/深色模式"不是一回事:

**系统设置 ▸ 外观 ▸ 图标与小组件样式**(Icon & Widget Style),四选一:**默认 / 深色 / 通透 / 色调**,
后三种还有 **自动 / 始终** 两种(自动 = 跟随系统的浅色/深色)。

- **默认**:图标就按开发者画的样子显示(背景的颜色都在)。**macOS 自带的 App 也一样** ——
  用户截图里深色模式下的 Dock,照片的白色花、访达的蓝白脸都还是原样,就是这个设置停在"默认"。
- **深色**:系统把图标的**背景**去饱和压暗,前景(我们那两卷胶片)保留颜色。
- **通透**:整个图标变成 Liquid Glass,**背景透出桌面壁纸** —— 想要"透明"就是这个,而且是*系统*
  给所有 App 的,不需要 App 做什么。
- **色调**:整体上一个系统色。

**文档这一侧该做的**:把深色底**写出来**(`fill-specializations` 里 `"system-dark"`),
这样"深色"这一档落在一个开发者认可的背景上,而不是让系统去猜 —— 实测写不写它,
`--rendition Dark` 逐位相同(系统本来就会兜底),但文档说了才是一个可复核的意图。

**为什么我之前的"读回"看不到这些档**:`NSWorkspace.icon(forFile:)` 在命令行进程里画的是
**默认外观**,所以从 bundle 读回永远得到浅色那一版 ✗ 它只能证明"图标进包了",
**要比较外观必须用 `ictool --rendition Default|Dark|ClearLight|ClearDark|TintedLight`**。

## 启动画面(2026-09-23,用户要求"更有质感、慢一点、强调色用 Apple 橙")

**它原来是什么**:360×190 的 `Theme.card` 上一行字、一行 "film simulation"、一个系统 spinner 加一行状态。

**现在**:一张 **360×194 的圆角卡片**,自上而下 —— **Silverphase** 字标(28 pt semibold)、
一行 tagline、**确定进度条**(Apple 橙、纯色,轨道是下沉的 well + 内描边)、底部一行状态 +
状态行(右侧原来那个 `NATIVE-METAL` 徽标**已拿掉** —— 见下)。进度条的三档就是三个相位
(`starting` 0.28 / `warming` 0.68 / `ready` 1.0),不是转圈:同一件事,状态行已经在说了。

**第二版(用户看了真窗口之后的两条)**:① "不用出现图标了…加上图标感觉整个版面太大了" ——
图标拿掉,字标和进度条就是全部信息,卡片因此收小到 360×194;② "顶部那一条黑条也很奇怪,
这里并没有窗口" —— 那是 `.titled` 窗口的**标题栏**:即使 `titlebarAppearsTransparent` +
`fullSizeContentView`,系统仍会在顶部画一条。所以窗口改成 **`.borderless` + 透明背景**,
卡片由视图自己画(圆角 14、L1 材质、1 px 内描边、自己的投影),窗口比卡片大 28 pt
—— **SwiftUI 的投影会被窗口裁掉**,不放大就没有投影;`hasShadow = false`,因为无边框窗口的
系统投影是**矩形**的,会和圆角卡片打架。

**"宁可慢一点"是明确要求,所以有了下限**:`BootWindowController.minimumOnScreen = 2.6 s`。
这是**人为的**,文件头里原来那句"nothing sleeps and nothing is padded"已经改掉并写明原因 ——
本机热启动只要 ~650 ms,不设下限时这个窗口只闪三分之二秒,读不出名字,也就不是品牌时刻。
下限只加在**成功**路径上:失败(能力拒绝)立刻交接,不能把"应用坏了"的解释扣在 logo 后面。
实测时序:`open` 后 0.9–3.3 s 屏幕上**只有**启动画面,3.7 s 出主窗口。

**顺带修掉一个潜伏的 bug**:文件头一直写着"Show it, hide the editor",但代码从来没隐藏过编辑器 ——
交接只要 0.65 s 的时候没人看得见,加了 2.6 s 下限之后,主窗口就明晃晃地停在启动画面后面。
现在 `present` 里隐藏一次,等待期间**每个 tick 再隐藏一次**(SwiftUI 随时可能把它 order in),
交接时只把它拿到最前。

**强调色**:进度条、徽标、失败图标都用 `Theme.accent`(Apple 橙 `#FF9F0A`),和界面一致;
进度条**纯色不渐变**(沿用"橙色不需要渐变了"那条)。tagline 的**字距只在英文里加** ——
中文加字距是每个字之间的缝,读起来像排版事故。

**抓图**:`--boot`(`--boot-phase starting|warming|ready`)渲染这一页,三档各一张,存
`modern_UI/design/snapshots/boot-*.png`。为什么不能用 `screencapture`:它要屏幕录制权限,
这个 harness 没有;而这个窗口的真实生命也只有 2.6 s。文案在字符串表里(`bootTagline` /
`bootStarting` / `bootWarming` / `bootReady`),相位行由 `Session.BootPhase.key` 查表。

## 字体：macOS 系统字体（2026-09-24）

界面统一使用 macOS 系统字体。设置页只提供界面缩放，不提供字体选择；应用不检测、加载或随包分发第三方字体。`Theme.Font` 仍按界面角色指定字号和字重，数值保留等宽数字特性。

**规则表**(代码里的 `Theme.Font`,pt / 字重 / 用在哪):

| 角色 | pt | 字重 | 用在哪 |
|---|---:|---|---|
| `railTitle`、`leftSectionTitle`、`sectionTitle` | 12 | **Semibold** | 栏标题、左栏分区标题(设置页与关于面板仍用兼容名 `sectionTitle`) |
| `rightSectionTitle` | 10.5 | **Semibold** | 右栏分区标题(直方图 / 白平衡 / 曝光 / 曲线 / 色彩平衡) |
| `body`、`filmLabel`、`edrLabel`、`label`、`tab` | 10.5 | **Regular** | **所有栏的控件标签**、EDR、下拉与药丸的标签、标签页 |
| `stockGroup`、`groupHeader` | 10.5 | **Medium** | 正片 / 负片 眉标、关于面板的字段名 |
| `zoomValue` | 10.5 | Medium + 等宽数字 | 缩放百分比 |
| `small`、`listItem`、`stockItem`、`asShot` | 9 | **Regular** | 列表行、胶片条目、"拍摄时设置" |
| `value`、`pill` | 9 | **Medium** + 等宽数字 | 每一个控件数值 |
| `action` | 13.11 | Medium | Developed / Original 两枚胶囊 |
| `cine` | 5.71 | Medium | CINE 徽标(§5 手记:需目检) |
| `meta`、`sublabel`、`caption` | 9 | **Light** | 说明文字:图注、禁用原因、画布状态、启动画面副标题 |

导出页是**另一张图纸**,有自己的刻度(`Theme.Font.Export`,冻结在 `eda971b` 的字面值):
`sectionTitle` 12.5 SemiBold、`label` / `listItem` 11 Regular、`chip` 11 Medium、
`value` 11 Medium 等宽数字、`pill` 9.5 Medium。它**不**跟着主界面的改动走,直到它自己的图纸被
翻译为止(TOKENS-v3 明说"Do not globally repoint `Font.Export`")。

**改掉的四处**:

1. **相机不再有第二套标签密度**(核心那条)。v3 给相机分区一个 **70 pt 的标签列 + 9 pt 的标签**,
   `Theme.Font.cameraLabel` 与 `Theme.Metric.cameraLabelWidth` 就是它;其它每个分区的标签是
   **84 pt 列 + 10.5 pt**。同一个栏里,测光方式比它下面的胶片曝光小一档半,而两者是同一层级 ——
   这不是层级,是图纸上两处不同的文字框。九个角色的字重分配本来就是为了让层级由**字重**说,
   不由**字号**说。现在 `SliderMetrics.camera` 这个预设被删掉,相机分行与胶片分行取同一个
   `Theme.Font.label` / `sliderLabelWidth = 84`。代价是相机的控件整体右移 14 pt(图纸里它们在
   x 86.35),换来的是一栏之内只有一条竖直的标签轴。
2. **正片 / 负片 眉标 Regular → Medium**。规则表里它一直是 Medium,代码却是 `body` 的
   Regular,于是列表的分组标题和它下面的胶片条目同重,读完像多了一行条目。
3. **设置 ▸ 诊断的读数**(`readout`):标签留在 `caption`(它说的是那个数,不是控件),**数值**
   改回 `value` —— 同样 9 pt,但 Medium + 等宽数字,和界面上每一个数字一致,跳动时也不左右挪。
4. **导出页四处串了刻度**:空态 / "Rendering the preview…" / 空工作列表 / `PillField` 的默认字体
   用的是**主界面**的 `Theme.Font.label`(10.5),而这一页其它文字是 11。改成本页的
   `Theme.Font.Export.label`,`PillField` 的默认值也一并改掉 —— 它今天的五个调用点都显式传了
   `F.label`,默认值只会害到下一个调用点。

**核对方法(可重跑)**:把 spektra 目录下每个 `.font(.system(` 的**文本**找出来(留着的只有
关于面板里那段 `.monospaced` 的许可证正文,那是有意的),再找每个没有设字体的 `Text`(剩下的都在
AppKit 菜单与 `.alert` 里,那是系统的字,不该动)。两条命令都干净:

```
grep -rn "\.font(\.system(" Spektrafilm/ | grep -v Image(systemName   # → 只有 AboutWindow 的许可证
grep -rn "\.custom(" Spektrafilm/                                    # → 空
```

**像素证据**(1:1,`--snapshot 1400x900`,右栏裁切):相机与胶片两行**同字不同行**的
`胶片`两字,墨迹框都是 42×22 px,逐像素最大差 3/255、超过阈值 8 的像素 **0 个** ——
同一字号、同一字重、同一字体。标签轴一律起于 x 16 pt;控件区起于 x 100 pt(= 16 + 84),
测光方式的药丸就落在这里。改动后 `LayoutTests`(9 例)与 `PanelResizeWiringTests`(4 例)全绿,
前者有两处断言从"相机另一列"改成"没有哪一栏还是相机那列"。
